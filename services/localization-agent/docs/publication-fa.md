# انتشار دستی پایلوت

انتشار با درخواست صریح صاحب پروژه انجام می‌شود؛ این درخواست به معنی بازبینی بومی یا
تغییر وضعیت پیش‌نویس‌ها به human_approved نیست. ابزار انتشار عضو MCP نیست و نقش
localization_service همچنان حق نوشتن در جداول اپلیکیشن ندارد.

`scripts/publish-pilot.py` پیش‌فرض dry-run است. برای اجرای واقعی، حساب اپراتور مستقل با
متغیر امن DATABASE_URL و `--execute` لازم است. credential اپراتور را به MCP یا مدل ندهید.
هیچ migration، کد Go، مسیر API یا منطق بک‌اند برای انتشار تغییر نمی‌کند.

## نگاشت به اپلیکیشن موجود

- معنی کارت جمله، عنوان گرامر و قاعده در content_translations با origin=machine ذخیره می‌شوند؛
  بک‌اند موجود آن‌ها را هنگام خواندن به payload اضافه می‌کند.
- هدف‌ها و عنوان نمایشی در lessons.objective، با نقشهٔ en/fa/ckb نگهداری می‌شوند.
  عنوان انگلیسی اصلی در lessons.title حفظ می‌شود؛ عنوان نمایشی در objective.title قرار می‌گیرد.
- توضیح و دستور تمرین در exercises.prompt به نقشهٔ زبان تبدیل می‌شوند؛ مقدار en عین متن اصلی است.
- فرانت‌اند عنوان نمایشی و دستور چندزبانه را انتخاب می‌کند. توضیح چندزبانه از قبل پشتیبانی می‌شد.
- answer_key، سؤال نمره‌دار، گزینه‌ها، ترتیب، رسانه و payload اصلی lesson_items تغییر نمی‌کنند.
- content_translations بر مبنای متن مشترک است؛ اگر همان عبارت در درس دیگری استفاده شود،
  همان ترجمه ممکن است آنجا نیز نمایش داده شود. ابزار ترجمهٔ موجودِ متفاوت را بازنویسی نمی‌کند.

فقط یک run با دو job کامل و مجموعهٔ کامل فیلدهای هر دو زبان پذیرفته می‌شود. هش مبدأ
پیش از نوشتن زیر قفل بررسی می‌شود. نوشته‌ها در یک تراکنش انجام می‌شوند. رسید خصوصی
شامل snapshot و مقادیر قبلی، قبل از commit روی دیسک ذخیره می‌شود. متن کامل یا credential
در گزارش عمومی و git قرار نمی‌گیرد. اصلاح‌های انتشار جدا ثبت می‌شوند و draft اولیه حفظ می‌شود.
اضافه‌شدن localeها هش زمینه را عوض می‌کند؛ پیش‌نویس‌ها نیازمند بازبینی باقی می‌مانند.
برای اجرای بعدی باید snapshot تازه گرفت؛ نسخهٔ قدیمی را دوباره enqueue/publish نکنید.
واردکردن مجدد درس ممکن است objective/prompt را از مبدأ بسازد؛ پس از re-import، نگاشت‌های
منتشرشده را دوباره بررسی کنید. پیش‌نویس‌ها جدا باقی می‌مانند و واژه‌نامهٔ content_translations
با re-import حذف نمی‌شود.

## نمونهٔ اپراتور

```bash
python scripts/publish-pilot.py --run RUN_UUID --lesson LESSON_UUID \
  --expected-hash SOURCE_HASH --receipt /SECURE/PATH/dry-run.json
# پس از بررسی dry-run و مجوز انتشار موجود:
python scripts/publish-pilot.py --run RUN_UUID --lesson LESSON_UUID \
  --expected-hash SOURCE_HASH --receipt /SECURE/PATH/publication.json --execute
```

رسیدها 0600 هستند. `--overrides` فایل JSON اختیاری با کلید
`source_type|source_id|field_path|locale` برای اصلاح مشخص تحریریه می‌پذیرد.
وجود رسید باعث توقف می‌شود؛ اگر وضعیت prepared ماند، وضعیت DB را با رسید تطبیق دهید و
بی‌بررسی تکرار نکنید. هیچ اجرای OpenAI یا هزینهٔ inference برای انتشار وجود ندارد.

## بازگشت همین انتشار

پیش از اجرا، بکاپ کامل دیتابیس و فایل‌ها و image قبلی فرانت‌اند گرفته شود.
برای بازگشت داده، ابتدا مطمئن شوید محتوا از زمان انتشار ویرایش نشده است؛ در تراکنش،
objective درس و prompt تمرین‌های همین درس را از بخش before رسید برگردانید.
فقط dictionary_afterهای همین رسید را که هنوز با مقدار منتشرشده برابرند حذف کنید و
dictionary_beforeها را بازگردانید. از بازگرداندن کل دیتابیس روی تغییرات جدید کاربران خودداری کنید.
برای فرانت‌اند image قبلی را بازگردانید؛ نیازی به restart بک‌اند یا rollback schema نیست.
