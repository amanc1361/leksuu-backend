# بستهٔ آمادهٔ تأیید برای دیتابیس اصلی

**SQL پس از درخواست کاربر برای ادامه و استقرار، در ۲۰۲۶-۱۰-۲۱ روی schema مستقل اعمال شد.**
این بسته پیش از درخواست استقرار برای بازبینی ارائه شده بود. گزارش نصب، بکاپ و آزمون‌های
واقعی در deployment-fa.md است. آن را دوباره روی نصب موجود اجرا نکنید.

## SQL دقیق

فایل‌ها SQL اجرایی کامل و بدون placeholder ساختاری هستند:

1. [001_up.sql](../sql/001_up.sql): schema جدید localization، سه جدول runs/jobs/drafts، index صف و تابع ثابت lock_source.
2. [002_role.sql](../sql/002_role.sql): نقش تازه localization_service با SELECT مبدأ و نوشتن محدود در localization؛ هیچ رمز داخل فایل نیست.
3. [003_audit.sql](../sql/003_audit.sql): بررسی مجوزهای واقعی پس از نصب.
4. [001_down.sql](../sql/001_down.sql): rollback دقیق؛ تمام داده‌های ترجمهٔ جدید را حذف می‌کند.

فایل 001 عمداً با CREATE SCHEMA عادی شروع می‌شود؛ اگر schema از قبل وجود داشته باشد،
توقف می‌کند تا داده یا نصب دیگری را بی‌بررسی بازنویسی نکند. پس از بررسی با DBA اجرا شود:

```bash
psql -X -v ON_ERROR_STOP=1 -f sql/001_up.sql
psql -X -v ON_ERROR_STOP=1 -f sql/002_role.sql
# در psql و با ورودی تعاملی امن: \password localization_service
psql -X -v ON_ERROR_STOP=1 -f sql/003_audit.sql
```

اتصال DBA با credential امن/PGSERVICE/PGPASSFILE باشد؛ URI واقعی را در فرمان قابل ثبت
یا خروجی ننویسید. runtime از این credential استفاده نمی‌کند. در همین پروژه ابزار
اجرای SQL دلخواه برای اجنت وجود ندارد.

## اثر و محدودیت

- هیچ ALTER/UPDATE/INSERT روی جداول public اپلیکیشن اجرا نمی‌شود؛ هیچ trigger جدیدی هم ندارند.
- هیچ دادهٔ اصلی پاک یا ترجمهٔ موجود اپلیکیشن منتشر نمی‌شود.
- تابع SECURITY DEFINER فقط SHARE lock روی پنج جدول آموزشی می‌گیرد. هنگام نهایی‌کردن
  پیش‌نویس، enqueue یا refresh، نوشتن اپلیکیشن ممکن است برای مدت کوتاه منتظر commit بماند.
  تابع SQL دلخواه نمی‌پذیرد و سرویس اجازهٔ UPDATE مبدأ ندارد.
- جدول drafts وضعیت human_approved دارد، ولی سرویس نمی‌تواند آن را تنظیم یا ترجمهٔ آن را بازنویسی کند.
- PUBLIC یا عضویت‌های نقش نباید دسترسی نوشتن مبدأ بدهند؛ audit باید آن را تأیید کند.
- استفاده از کلید فعلی با دستور صریح کاربر انجام شد؛ کلید فقط در secret کنترل‌گر خارج از git است.

## gateway آماده

فایل [leksuu.caddy.proposed](../config/leksuu.caddy.proposed) نسخهٔ قابل بررسی مبتنی بر
فایل فعلی سرور است. مسیر `/localization/*` به سرویس مستقل اضافه می‌کند؛ APIهای فعلی
اپلیکیشن تغییر نمی‌کنند. backup، validate و reload لازم‌اند. مسیر عمومی پیشنهادی
`https://leksuu.ir/localization/mcp` است و DNS تازه نمی‌خواهد. زیردامنه نیازمند دسترسی
واقعی به DNS است؛ چنین دسترسی‌ای در این جلسه تأیید نشده است.

## بازگشت

ابتدا کنترل‌گر/MCP را متوقف کنید و gateway را از backup برگردانید.
با DBA از schema localization پشتیبان بگیرید. سپس در صورت خواست حذف تمام پیش‌نویس‌ها:

```bash
psql -X -v ON_ERROR_STOP=1 -f sql/001_down.sql
```

حذف نقش اختیاری، پس از لغو grantها با DBA انجام شود. در هیچ مرحله‌ای rollback جداول
آموزشی یا public.content_translations را حذف/تغییر نمی‌دهد.

## وضعیت پس از استقرار

SQL و HTTPS اجرا و آزمایش شدند؛ تأیید مجدد نصب لازم نیست. دسترسی واقعی Agents و
پایلوت پولی یک درس با سقف مجاز ۵ دلار انجام شد: ۳۴ پیش‌نویس نیازمند بازبینی انسانی.
کنترل هزینهٔ مبتنی بر polling/cancel سقف سخت سمت OpenAI نیست؛ worker دائمی فعال نیست.
اجرای گسترده و انتشار منتظر تأیید پایلوت و بازبینی بومی سورانی هستند.
