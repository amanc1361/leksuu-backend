# پنل مدیریت ترجمه

مسیر پنل: `/fa/admin/localization`؛ در منوی ادمین «مدیریت ترجمهٔ دوره‌ها».
نسخه‌های `/ckb/admin/localization` و `/en/admin/localization` نیز وجود دارند.

## کار با پنل

۱. در «تنظیم سرویس و مدل هوش مصنوعی»، OpenAI، Google Gemini یا سرویس سازگار با
OpenAI را انتخاب کنید. نام مدل دلخواه و کلید API را ثبت کنید. برای سرویس سازگار،
آدرس پایهٔ HTTPS عمومی، مانند آدرسی که به `/v1` ختم می‌شود، لازم است.
قیمت جاری یک میلیون توکن ورودی و خروجی شامل reasoning را وارد کنید. قیمت باید
با مدل و اندازهٔ زمینهٔ درخواست تطبیق داشته باشد؛ پنل قیمت مدل‌ها را حدس نمی‌زند.
کلید قبلی به مرورگر برنمی‌گردد؛ خالی گذاشتن فیلد کلید هنگام ویرایش، آن را حفظ می‌کند.

۲. با «بررسی اتصال و دریافت مدل‌ها» فهرست مدل‌های حساب را بخوانید یا نام مدل را
مستقیماً وارد کنید. دیده‌شدن مدل در فهرست، داشتن سهمیهٔ inference را تضمین نمی‌کند.
هر تنظیم ذخیره‌شده یک نام و مدل دارد؛ برای مقایسهٔ مدل‌ها چند تنظیم بسازید.

۳. زبان دوره، سطح، دوره، چپتر و زبان مقصد فارسی یا سورانی را انتخاب کنید.
فهرست‌ها و شمارنده‌ها از دیتابیس زنده خوانده می‌شوند. درس‌ها را انتخاب کنید و
سقف هزینهٔ اجرای جدید را مشخص کنید؛ سپس «ترجمهٔ بخش‌های ناقص» را بزنید.
یک چپتر یا کل دوره با انتخاب همهٔ درس‌های نمایان قابل پردازش است. در دوره‌های
بزرگ‌تر از ۵۰۰ درس، چپتر را انتخاب کنید. هر اجرا حداکثر ۵۰۰ درس دارد.

۴. با کلیک روی نام درس، تمام فیلدهای مجاز به ترجمه را ببینید. وضعیت هر کدام
«ترجمه‌نشده»، «در صف»، «در حال اجرا»، «پیش‌نویس»، «منتشرشده»، «خطا» یا «نتیجهٔ
نامعلوم» است. فیلتر، جست‌وجوی متن اصلی/ترجمه و نشان تغییر مبدأ وجود دارند.
ترجمه‌های قبلی در `content_translations` و فیلدهای چندزبانهٔ درس هم شناسایی می‌شوند.

۵. برای یک عبارت، متن را دستی ویرایش و «ذخیرهٔ پیش‌نویس دستی» را بزنید، یا فقط
همان بخش را دوباره با مدل انتخابی تولید کنید. تغییر دستی هم‌زمان با worker حفظ
می‌شود. هر retry یک اجرای جدید با بودجهٔ جداست؛ کارهای فعال تکرار نمی‌شوند.

۶. پس از بازبینی، «انتشار همین پیش‌نویس» یا انتشار پیش‌نویس‌های انتخاب‌شده را بزنید.
تولید AI به‌تنهایی چیزی را منتشر نمی‌کند. برای جایگزینی ترجمهٔ متفاوت در واژه‌نامهٔ
مشترک باید اجازهٔ مربوط را صریحاً فعال کنید؛ این تغییر می‌تواند روی درس‌های دیگری
که همان جمله را استفاده می‌کنند اثر بگذارد. وضعیت تأیید بومی سورانی خودکار ثبت نمی‌شود.

## پوشش و حفظ داده

نگاشت همان سرویس قبلی استفاده می‌شود: عنوان نمایشی، هدف‌ها، قاعده و عنوان گرامر،
معنی عبارت، دستور و توضیح تمرین و سؤال‌های آشکارا راهنما. مثال‌های زبان آموزشی،
پاسخ صحیح، گزینه‌ها، ترتیب، رسانه و سؤال‌های نمره‌دار بازنویسی نمی‌شوند.
فیلدهای فاقد نگاشت یا مبهم به‌عنوان محتوای محافظت‌شده شمارش می‌شوند؛ آمار تکمیل
به معنی ترجمهٔ متن آموزشیِ عمداً محافظت‌شده نیست. هر فیلد مجاز یک واحد مستقل است؛
قاعدهٔ چندجمله‌ای/HTML یک فیلد باقی می‌ماند تا ساختار و placeholderهایش حفظ شوند.

ترجمه و بازبینی دو درخواست جدا هستند و از همان glossary، schema و validator
استفاده می‌کنند. خطاهای اتصال/سهمیه و کنترل مبدأ برای هر بخش ذخیره می‌شود. در
timeout نتیجه و هزینه ممکن است نامعلوم باشد؛ درخواست خودکار تکرار نمی‌شود.
قبل از هر درخواست، هزینهٔ محافظه‌کارانه رزرو می‌شود. این کنترل بودجه بر مبنای
نرخ واردشدهٔ ادمین است و تضمین سقف صورتحساب ارائه‌دهنده نیست.

## معماری و دسترسی

- Go API مسیر `/api/v1/admin/localization/` را با `RequireRole("admin")` محافظت
  می‌کند؛ JWT کاربر را به سرویس داخلی منتقل نمی‌کند و هویت ادمین را از context می‌گیرد.
- سرویس Python در شبکهٔ داخلی Docker و بدون پورت منتشرشده اجرا می‌شود و علاوه
  بر آن bearer token داخلی مستقل و شناسهٔ ادمین می‌خواهد.
- صف، پیش‌نویس، وضعیت و گزارش ویرایش/انتشار در schema مستقل `localization_admin`
  هستند. داده‌های پایلوت قبلی در schema `localization` دست‌نخورده می‌مانند.
- نقش `localization_admin_service` کاربران، حساب‌ها و پرداخت‌ها را نمی‌خواند؛
  فقط جداول آموزشی و واژه‌نامه را می‌خواند و اجازهٔ تغییر ستون‌های نمایشی لازم را دارد.
- کلیدها در volume خصوصی `admin-state`، فایل‌های 0600 نگهداری می‌شوند. در
  پاسخ API، log، image، سورس یا Git قرار نمی‌گیرند. از این volume هم بکاپ خصوصی بگیرید.
- فقط یک replica از workspace اجرا شود؛ startup درخواست درحال اجرای قبلی را
  نامعلوم علامت می‌زند. برای توقف درحال کار، مهلت ۱۵۰ ثانیه برای پایان HTTP دارد.

## اجرای سرور

نصب اولیهٔ root، پس از آماده‌بودن سرویس localization قبلی:

```bash
cd /opt/leksuu/leksuu-backend/services/localization-agent
python3 scripts/install-admin-server.py
docker compose -f compose.admin.yml build workspace
docker compose -f compose.admin.yml up -d workspace
```

installer بکاپ کامل دیتابیس را با `pg_restore --list` بررسی می‌کند، schema و نقش
محدود را می‌سازد و secretهای اتصال داخلی را بدون چاپ مقدارشان تنظیم می‌کند.
پس از build API و frontend، فقط همان سرویس‌ها با `--no-deps` بازسازی شوند؛
هیچ seed یا migration قدیمی دوباره اجرا نشود.

بکاپ نصب این نسخه: `/root/localization-admin-install-20261023T150209Z`؛ بکاپ سورس:
`/root/localization-admin-source-20261023T150154Z`.

Google روی مسیر مستقیم سرور قبلاً 403 می‌داد و حساب Argon سهمیهٔ صفر داشت.
پنل این خطاها را نشان می‌دهد؛ رفع سهمیه/اعتبار و شبکهٔ ارائه‌دهنده همچنان لازم است.
برای پراکسی معتبر روی سرور می‌توان `LOCALIZATION_AI_PROXY` را در فایل خصوصی
`/opt/platform/secrets/localization-admin.env` تنظیم و فقط workspace را بازسازی کرد.
پراکسی `127.0.0.1` ماشین توسعه روی سرور معتبر نیست.

## توقف و بازگشت

ابتدا اجراهای فعال را از پنل pause کنید؛ سپس در صورت نیاز:

```bash
docker compose -f compose.admin.yml stop workspace
```

imageهای قبلی API/frontend و فایل env قبلی در بکاپ نصب ثبت شده‌اند. برای بازگشت
پنل، از همان imageها و env استفاده کنید؛ schema/volume را حذف نکنید تا پیش‌نویس‌ها
باقی بمانند. برای برگرداندن ترجمهٔ منتشرشده، رویداد `publish` در جدول audit مقدار
قبل/بعد را دارد؛ فقط پس از بررسی نبود ویرایش جدید، همان فیلد برگردانده شود.
دیتابیس کامل را روی داده‌های تازهٔ کاربران restore نکنید.

## اعتبارسنجی

۶۵ آزمون Python با PostgreSQL جداگانهٔ واقعی، تمام آزمون‌های Go، TypeScript،
lint فایل‌های جدید و production build محلی Next.js موفق بودند. تست‌های نوشتن و
انتشار روی دیتابیس تست جدا اجرا شدند؛ نصب پنل به‌خودی‌خود ترجمهٔ پولی اجرا نمی‌کند.


### مدل‌های متعدد برای هر سرویس
در تنظیمات سرویس‌ها، «افزودن مدل به این سرویس» را بزنید. شناسهٔ مدل، نام نمایشی، هزینهٔ ورودی و خروجی به دلار برای هر یک میلیون توکن و یادداشت کارایی/کاربرد را وارد کنید. مدل جدید کلید همان سرویس را در سمت سرور استفاده می‌کند؛ تغییر کلید سرویس به تمام مدل‌های وابسته اعمال می‌شود. نرخ‌ها را خود مدیر مطابق قرارداد سرویس وارد می‌کند. در بخش اجرای ترجمه، ابتدا سرویس و سپس مدل را انتخاب کنید. قیمت‌ها و یادداشت مدل انتخاب‌شده نمایش داده می‌شوند. تنظیمات قبلی به عنوان مدل اول هر سرویس حفظ می‌شوند.


### نتیجهٔ ترجمه و نمایش در دوره
وارد شدن به صف و پایان تولید پیش‌نویس به معنی انتشار در دوره نیست. سابقهٔ اجرا، نام دوره/چپتر/درس، زمان، تعداد بخش‌ها، خطاهای سرویس و شمار پیش‌نویس‌ها و بخش‌های منتشرشده را نشان می‌دهد. از «بازبینی نتیجه و انتشار در دوره» وارد همان درس و زبان شوید و متن و نکته‌های بازبینی را بررسی کنید؛ سپس «انتشار پیش‌نویس‌های این درس در دوره» را بزنید. انتشار هزینهٔ هوش مصنوعی ندارد. بخش‌های محافظت‌شده و پاسخ‌ها انگلیسی باقی می‌مانند. اجرای بدون بخش جدید به عنوان «ردشده» ثبت می‌شود و نام درس انتخابی را نگه می‌دارد. برای ارتقای نصب قدیمی، پس از پشتیبان‌گیری اسکریپت `sql/005_run_scope.sql` را با دسترسی مالک دیتابیس اجرا کنید.
